## 0. How to read this document

This document is the **briefing instrument** for WS07: the six separate mandates given to six independently-run concept studios, plus the **isolation protocol** that lets them share one evidence base while being structurally prevented from seeing each other's concepts before the first cross-studio review (`prd.md` §8). It is the artifact that satisfies the TASK-043 acceptance criteria: *six separate briefs* (Behavior First, Joy First, Invisible App, Health Intelligence, Life Companion, Category Breaker) that **share evidence but prohibit cross-studio concept viewing.**

It is a **governance / method artifact**, not a research finding and **not a concept.** It contains:
- **no concepts, ideas, wireframes or storyboards** — those are the studios' work (`prd.md` §8; the submission *format* is `→ TASK-044`, not this document);
- **no fabricated research** — no interview, observation, metric, effect size, user quote or clinical outcome is asserted here; the shared evidence package (§2) is referenced **by record ID and version**, not reproduced or invented;
- **no claim that any upstream input is populated** — several inputs (Opportunity Atlas, Capability decisions, user findings) are produced by tasks that, at this writing, exist as *schemas and rubrics* (`↔ TASK-041/042`, `→ TASK-030/035`), not as populated data. The briefs are therefore **released only against an approved, versioned package snapshot** (§2.2); until that snapshot exists, these briefs are a *template ready to be filled and issued*, not a live commission.

> **No-fabrication statement.** This document briefs studios; it does not do their work and it invents no evidence. It cites no real `OPP`, `NEED`, `EVD`, `CAP`, `JRN` or `APP` content; where it names a problem space it does so as a *pointer to the Atlas territory that will carry the real evidence*, clearly marked. It asserts no concept's desirability, no test result, and no user preference. The illustrative material in §5–§10 describes **what each studio is asked to do and must avoid** — never what any studio produced. The design is built to make fabrication detectable and inert: (a) a brief may be *issued* only after the Program Director approves the Atlas snapshot and its version hash (§2.2 / §7 hard stop); (b) every studio claim must later carry an **evidence-vs-invention label** (`prd.md` §11; enforced at submission `→ TASK-044`), so an invented mechanism can never masquerade as a finding; (c) "Never present imagined preferences as validated" (`prd.md` §13 Prompt 09) is reproduced as a hard rule in every brief (§4.6); (d) concepts are judged later by independent validation (`→ TASK-048`), never self-certified by the studio.

**Scope boundary (what this task is and is not).**
- **TASK-043 (this document) = the six *briefs* + the *isolation protocol* + the *shared-package contract*.** It defines, per studio, the mandate, the framing question, the lens, the emphasis across the Atlas territories, the constraints, the self-critique agenda, the studio-specific traps, and the required outputs *at the level of what to produce* — and it defines how the studios stay independent.
- **TASK-044 (divergent concept submission template) = the *output format*** the studios submit into: the 15-idea catalogue structure, the three-dossier structure, the evidence/invention labels, the risk fields, the lead-concept field and completeness validation. This document **points to** that format (§4.5) and does not re-define it.
- **TASK-045 (eight-screen wireframe spec) = the low-fidelity screen specification** the studios' prototypes are built against; referenced (§4.5), not defined here.
- **TASK-032 (90-minute capability workshop script) = a *capability-extraction* facilitation artifact (WS02/Phase 3), not a concept studio.** Different stage, different purpose; this document does not reuse it.
- **TASK-041 / TASK-042 (Opportunity Atlas schema / prioritization rubric) = the *input* these briefs consume.** The approved, prioritized, territory-mapped Atlas is the spine of the shared package (§2); this document does not re-derive opportunities or territories, it *references* them.
- **TASK-048 (concept testing & final selection) = the *downstream* judge.** These briefs set up concepts to be tested there; they never pre-judge or self-score desirability.

## 1. Purpose and non-negotiables

`prd.md` §8 commissions **six independent concept studios**, each with a distinct mandate, all receiving "the same versioned evidence package, opportunity atlas, capability decisions, real user findings, brand principles, clinical/privacy/accessibility constraints and success measures," and all bound by one rule: they "must **not** see each other's initial designs before the first review." Prompt 09 (§13) adds the five-step method each studio runs and the independence rule ("Do not copy competitor feature lists or see other studios' first-round designs"). §7 sets the hard precondition: "Gate approval before concept studios begin."

These briefs exist to do six jobs:

1. **Issue six genuinely different mandates.** Each studio is pointed at the *same* evidence through a *different lens* so the Lab gets "six meaningfully different product visions" (`prd.md` §1), not six variations on one. The mandates are the PRD §8 table, reproduced verbatim and then operationalized into a framing question, an emphasis and a self-critique agenda.
2. **Give every studio the identical shared package.** Divergence must come from *interpretation*, not from unequal information. §2 defines a single versioned, hashed package every studio receives in full — including the parts that complicate its own mandate.
3. **Prohibit cross-studio concept viewing until the first review.** §3 is the isolation protocol: what is shared (evidence) versus sequestered (ideas, concepts, storyboards, lead picks), how studios are kept apart, and what counts as a leak.
4. **Fix the common output contract.** Every studio runs the same method and submits the same shape of deliverable (§4), so the §11 Gate 3 review and the `→ TASK-048` validation can compare like with like — without homogenizing the concepts themselves.
5. **Carry the non-negotiable constraints into every brief.** Clinical safety, privacy/data-minimization, accessibility, user autonomy and the non-patronizing HerRays brand are mandatory gates in all six briefs (`prd.md` §8/§9/§11), not studio-specific options.
6. **Keep invention honest.** Studios are *encouraged* to invent (that is the point of WS07), but every invented mechanism is labelled as invention, not evidence, and no concept's appeal is asserted as validated (`prd.md` §11/§13).

**Seven non-negotiable rules, enforced across all six briefs:**

- **B1 — Gate before commission.** No brief is issued, and no studio begins, until the Program Director has issued **pass** on the Atlas-release gate (`prd.md` §7) and recorded the approved package version (§2.2). Commissioning a studio against an unapproved or unversioned package is a forbidden action (§12).
- **B2 — Identical package, in full.** Every studio receives the *same* package version, including territories and evidence that cut against its own mandate. Curating the package per studio (hiding inconvenient evidence, pre-selecting "their" territories) is forbidden (§12); emphasis is expressed in the brief, never by withholding evidence.
- **B3 — Evidence is shared; concepts are sequestered.** Ideation catalogues, concept dossiers, storyboards, prototypes and lead-concept picks are **not** shared between studios before the first review (`prd.md` §8). Shared repository evidence (`APP/EVD/JRN/CAP/NEED/OPP/DEC`) *is* shared. §3 draws the line precisely.
- **B4 — No competitor feature-copying.** "Do not build a collage of competitor features" (`prd.md` executive mandate); "Do not copy competitor feature lists" (Prompt 09). Benchmark material is *reference pattern*, not a shopping list; every adoption must trace to a mechanism and an evidence basis, not to "App X has it."
- **B5 — Invention is labelled, never laundered into evidence.** Each idea and concept element is tagged *evidence-based* / *adapted* / *invented* (`prd.md` §11; format `→ TASK-044`). An invented mechanism may be pursued, but it may never be presented as a finding, and its appeal is a hypothesis to test (`→ TASK-048`), not a result.
- **B6 — Mandatory constraints are non-compensable.** Clinical safety, privacy/data-minimization, accessibility and user autonomy are gates, not trade-offs. A delightful or novel concept that fails any of them does not pass Gate 3 (`prd.md` §9/§11). No studio's lens exempts it — least of all the two whose mandates sit nearest the clinical and autonomy edges (Studios D and C/E).
- **B7 — No fabricated users, preferences or results.** "Never present imagined preferences as validated" (`prd.md` §13 Prompt 09). Studios reason *from* the shared user findings (`NEED`, `→ TASK-029`); they do not invent participants, quotes, adoption, retention or outcomes. Where a concept needs a signal that does not yet exist, the studio writes a **test hypothesis** for `→ TASK-048`, not a claimed result.

## 3. The isolation protocol (share evidence, sequester concepts — B3)

This section is the operational core of the acceptance criterion "share evidence but prohibit cross-studio concept viewing."

### 3.1 The sharing line

| Always shared (identical to all) | Sequestered until the first cross-studio review |
|---|---|
| The `PKG` package P1–P10 (§2), including version + hash | A studio's **ideation catalogue** (its ≥15 ideas) |
| Repository evidence: `APP/EVD/JRN/CAP/NEED/OPP/DEC` | A studio's **three concept dossiers** |
| Brand, clinical, privacy, accessibility constraints | Its **storyboards and low-fi prototypes** |
| Success measures & validation dimensions | Its **lead-concept pick** and internal critique |
| The *common* brief spine (§4) and the isolation rules | Any framing/renaming that would reveal its direction |

**Rule of thumb:** *inputs* (evidence, constraints, problem space, success criteria) are common property; *outputs* (ideas and concepts) are private to each studio until the §11 Gate-3 first review. Benchmark apps are shared *as evidence* (P5), but a studio never sees how a sibling studio *used* them.

### 3.2 Separation mechanisms

- **S-1 Separate workspaces.** Each studio works in its own repository space / channel / file tree with no read access to the other five studios' concept folders. Only the Program Director (independence custodian) and the designated reviewers have cross-studio read access, and only after submission.
- **S-2 Independent instances (Prompt 09 "run six isolated copies").** Each studio is a separate instance/team with no shared concept memory; a single person contributing to two studios (staffing may overlap, `prd.md` §2) must not carry one studio's concepts into another and signs the S-6 attestation for each.
- **S-3 One-way evidence, no concept back-channel.** Studios may query the *shared evidence* freely (and should — it is identical for all), but there is no channel by which one studio's ideas reach another before the review. Questions about evidence go to the Program Director, who answers from the shared package so every studio hears the same answer.
- **S-4 Synchronized package only.** The only thing pushed to all studios mid-cycle is a new `PKG` version (§2.2) — never another studio's work product.
- **S-5 Timed reveal.** Concept visibility opens at the **first cross-studio review** (Gate 3, `prd.md` §8/§11), not before. Up to that moment, no studio has seen another's ideation, concepts, storyboards or lead pick. After it, cross-pollination is allowed and encouraged under the program director's framing.
- **S-6 Independence attestation.** On submission, each studio attests: "We received `PKG-v<x>` (hash …); we did not view any other studio's first-round ideas, concepts, storyboards or lead concept; our concepts are our own interpretation of the shared evidence." The attestation is logged with the submission.

### 3.3 What counts as a breach (and the response)

- Viewing, receiving or being shown another studio's ideation/concepts/storyboards/lead pick before the first review → **independence breach**; the affected concepts are flagged and may be quarantined from the comparative validation to protect the comparison (`prd.md` §8). The breach is logged, not buried.
- Receiving a differently-curated package (missing or extra evidence vs siblings) → **package-integrity breach** (violates B2); the studio is re-issued the canonical `PKG` and prior work is re-checked for information it should not have had.
- A reviewer leaking one studio's direction to another before the review → custodian escalation; same quarantine logic.

> **Why isolation matters (rationale, not decoration).** Independence is what makes the later comparison meaningful: six studios converging *despite* isolation is strong signal that a direction is robust; six diverging gives the Lab a genuinely wide option space to test (`→ TASK-048`). If studios saw each other early, they would anchor on the first attractive concept and the Lab would get one idea wearing six hats — exactly the "collage" the mandate forbids. Isolation is a *de-biasing instrument*, enforced by structure, not by asking people to be fair.

## 4. The common brief spine (identical structure for all six studios)

Every studio brief below (§5–§10) is issued with this shared spine filled in from the PKG. The spine fixes *what every studio does the same*; §5–§10 fix *what each does differently* (B1-driven divergence).

### 4.1 Standing mandate (same for all)
Produce a meaningfully different, clinically-responsible, enjoyable product vision for women in midlife, grounded in the shared evidence, through this studio's distinct lens — without copying competitor feature lists and without seeing other studios' first-round work (`prd.md` §8/§13).

### 4.2 Method (same five steps — Prompt 09)
1. **Interpret** the shared evidence and the Atlas through this studio's lens: name the root problems *this* studio will attack and why.
2. **Diverge:** generate **at least 15 genuinely distinct ideas** (not 15 variants of one). Breadth is graded (`→ TASK-044`).
3. **Critique:** challenge the ideas against evidence, user needs, **autonomy, accessibility, feasibility and differentiation** — and against this studio's named traps (§5–§10).
4. **Develop three contrasting concepts.** For each: proposition, user promise, interaction model, behavioral logic, novel/invented elements, and the four required journeys — **first-use, ordinary-day, missed-day, long-term** — plus risks and unknowns.
5. **Prototype:** storyboards + low-fidelity, editable/clickable prototypes (screens per `→ TASK-045`).

### 4.3 Mandatory constraints (same for all — B6, non-compensable)
Clinical safety & care boundaries (`→ TASK-040`, R14) · privacy & data-minimization / no unsupported medical claims (`→ TASK-040`, R15) · accessibility: VoiceOver, Dynamic Type, contrast, reduced-motion, adequate targets (`→ TASK-022`, R13) · **user autonomy & anti-dark-pattern** (no shame, forced streaks, manipulative urgency, or guilt loops — `prd.md` §6) · **non-patronizing brand** voice (`prd.md` §13 Prompt 00, P6).

### 4.4 Success orientation (same for all — P8)
Design toward the §1 separation of **engagement vs adherence vs automaticity vs health outcomes** and the zero-guilt North Star (`↔ TASK-001`): meaningful *repeated action and perceived autonomy*, "not merely app opens" (`prd.md` §3 line 135). Concepts must be *testable* on the §9 validation dimensions — desirability, comprehension, first-action completion, perceived effort, trust, differentiation, accessibility, return intent, willingness to pay.

### 4.5 Required outputs & submission (same for all)
Per Prompt 09, each studio delivers an **ideation catalogue (≥15 ideas)**, **three concept dossiers**, **storyboards + low-fi prototypes**, **evidence/invention traceability**, feasibility notes and **test hypotheses**. Across six studios this yields the **18 initial concept dossiers** the PRD expects (`prd.md` §8). The **exact submission format, field list, evidence/invention labels and completeness validation are defined in `→ TASK-044`**; the wireframe/screen spec in `→ TASK-045`. This brief sets the mandate and constraints; it does not restate the template.

### 4.6 Hard rules reproduced into every brief
B4 (no competitor feature-copying) · B5 (label invention, never launder it into evidence) · B7 ("Never present imagined preferences as validated" — write a test hypothesis, not a result) · S-6 (sign the independence attestation on submission).

## 5. Studio A — Behavior First

> **Mandate (verbatim, `prd.md` §8):** Make change achievable for people who repeatedly abandon habits.

- **Framing question:** For the woman who has started and quit many times, what makes the *next* attempt the one that survives a bad week — without shame, rigidity, or all-or-nothing collapse?
- **Lens / worldview:** Behavior change as engineering of **initiation, repetition, recovery and autonomy** (COM-B, BCTTv1, SDT, Fogg, implementation intentions; P4). The "streaks" worked example (`prd.md` §3 line 135) is this studio's home turf: reinforcement and feedback *without* the shame and all-or-nothing failure modes. Lean on the **recovery-after-miss** and **flexible-consistency** mechanisms and the zero-guilt North Star (`↔ TASK-001`).
- **Atlas emphasis (not exclusivity — B2):** weight territories about *lapse, recovery, restarting, low-friction initiation and autonomy-preserving reminders*; still read the whole Atlas, including territories that pull toward delight or health context.
- **What a strong concept looks like here:** demonstrably lowers the cost of *restarting*; turns a missed day into a non-event or a re-entry, never a reset; makes the *minimum viable action* feel achievable on a low-energy day; measurably targets **adherence/automaticity**, not engagement counts.
- **Self-critique agenda (Step 3):** Does this reduce guilt or smuggle it back in (e.g., a "don't break the chain" mechanic rebranded)? Does it respect autonomy or nag? Is it evidenced by the BCT matrix (P4) or asserted? Does it help *repeated abandoners* specifically, or only disciplined users?
- **Studio-specific traps to avoid:** punitive streak resets; loss-aversion pressure dressed as motivation; over-tracking burden; "gamification" that boosts opens but not meaningful action; advice that is correct but patronizing.

## 6. Studio B — Joy First

> **Mandate (verbatim, `prd.md` §8):** Create emotional delight and intrinsic return value.

- **Framing question:** What would make a woman *want* to open this — not out of obligation or fear of losing a streak, but because it is genuinely pleasurable and feels like hers?
- **Lens / worldview:** **Intrinsic motivation and affect** — SDT's autonomy/competence/relatedness (P4), emotional response, visual/motion craft (R04/R08), the "(Not Boring) Habits" delight question (`prd.md` §3) interrogated for *cost*: does the delight serve the behavior or distract from it? Pair joy with the §9 **return-intent** and **delight** dimensions while keeping **effort** low.
- **Atlas emphasis:** weight territories about *reassurance, felt progress, emotional appeal and return value*; read the rest in full.
- **What a strong concept looks like here:** return is driven by *intrinsic* pull (pleasure, meaning, identity), not extrinsic pressure; delight is legible to a midlife audience (not juvenile); novelty earns its interaction and performance cost; emotional payoff is tied to *real* progress, not empty celebration.
- **Self-critique agenda:** Is the delight *intrinsic* or a dressed-up extrinsic hook? Does the animation/novelty cost (performance, accessibility, reduced-motion) justify itself (`prd.md` §3 "Novelty and animation costs need testing")? Is "joy" patronizing or infantilizing for this audience? Does delight survive the **reduced-motion** path (B6)?
- **Studio-specific traps to avoid:** novelty-over-utility; animation that breaks reduced-motion or Dynamic Type; celebration disconnected from meaningful action (hollow confetti); cuteness that reads as condescension to women in midlife; delight that raises daily effort.

## 7. Studio C — Invisible App

> **Mandate (verbatim, `prd.md` §8):** Deliver meaningful value with minimal daily screen interaction.

- **Framing question:** How can the product help the behavior happen in the world with *as little in-app time as possible* — succeeding when the user barely opens it?
- **Lens / worldview:** **Ambient / low-interaction** design — widgets, Live Activities, notifications, on-device intelligence, Shortcuts, glanceable surfaces (P9; `→ TASK-039`). Inverts the engagement model: success is *less* screen time, more real-world action. Directly serves the final decision rule — "least unnecessary effort" (`prd.md` §15).
- **Atlas emphasis:** weight territories about *low-friction initiation, autonomy-preserving reminders and reducing app burden*; read the rest in full.
- **What a strong concept looks like here:** delivers value at a glance or hands-free; reduces, not increases, daily interactions while still moving **adherence**; respects attention and autonomy; degrades gracefully when notifications are off.
- **Self-critique agenda:** If the app is invisible, how is value *delivered and felt*? How is the behavior still *supported* rather than merely untracked? Does "minimal interaction" risk losing the behavior-change mechanism entirely? Are notifications helpful or nagging (autonomy, B6)? Does it work for users who disable widgets/notifications?
- **Studio-specific traps to avoid:** confusing *no app* with *no support* (losing the mechanism); notification over-reliance that becomes nagging; value that evaporates without permissions the user may deny; invisibility that hides important safety/clinical information the user needs to see.

## 8. Studio D — Health Intelligence

> **Mandate (verbatim, `prd.md` §8):** Connect daily choices to personally relevant health context.

- **Framing question:** How can everyday actions be made meaningful by connecting them to *this woman's* health context — credibly, safely, and without turning her into a data analyst or a patient?
- **Lens / worldview:** **Relevance through personalization and appropriate clinical integration** — HealthKit, longitudinal health intelligence, HerRays physician-led care boundaries (P7/P9; `→ TASK-039/040`). This is the studio nearest the clinical edge, so **B6 clinical/privacy gates bind hardest here** (R14/R15 co-review mandatory). The §7 example — "reassure users that their efforts matter without forcing them to become data analysts" — is this studio's tension.
- **Atlas emphasis:** weight territories about *relevance to midlife context and connecting daily life to care*; read the rest in full. Note: the Atlas must carry clinical-integration *and* non-clinical opportunities (`↔ TASK-042 PV-3`), so this studio does not own health context alone.
- **What a strong concept looks like here:** makes a daily action feel personally relevant via credible, consented health context; stays strictly inside care boundaries (no diagnosis, no unsupported medical claims); minimizes and protects sensitive data; connects to clinician workflows only where appropriate and consented.
- **Self-critique agenda:** Does any element imply diagnosis, treatment efficacy or a medical claim without evidence (`prd.md` §4/§11; **unsupported-claims gate**)? Is sensitive health data minimized, consented and access-controlled (R15)? Does it medicalize a lifestyle product or make the user feel like a patient? Does personalization require data the user shouldn't have to give?
- **Studio-specific traps to avoid:** medical overreach / implied clinical efficacy; anxiety-inducing health framings; data-maximalism ("collect everything"); personalization that is creepy rather than caring; blurring the line between lifestyle guidance and clinical advice.

## 9. Studio E — Life Companion

> **Mandate (verbatim, `prd.md` §8):** Adapt to changing energy, schedules and priorities.

- **Framing question:** How can the product meet a woman where she actually is on *this* day — low energy, unpredictable schedule, shifting priorities — instead of demanding a fixed routine?
- **Lens / worldview:** **Adaptivity and context** — the provisional segments and real behavioral segments (P3; `prd.md` §5: unpredictable schedule, low-energy day, changed circumstances), fluctuating capacity, life-stage transitions. Companionship over compliance; the product bends to the person, not the reverse.
- **Atlas emphasis:** weight territories about *adapting to fluctuating energy and unpredictable schedules, and changed circumstances*; read the rest in full.
- **What a strong concept looks like here:** visibly adapts to energy/schedule/priority changes; offers a graceful "small version" on hard days; treats life disruption (travel, illness, caregiving load) as expected, not as failure; sustains **adherence** across changing contexts rather than rewarding only ideal days.
- **Self-critique agenda:** Does adaptation require *surveillance* or burdensome input to know the user's state (autonomy/privacy, B6)? Is "companion" warm or cloying/patronizing? Does it genuinely flex, or just relabel the same fixed plan? How does it behave when it *doesn't* know the user's current state?
- **Studio-specific traps to avoid:** surveillance creep to fuel adaptation; input burden that defeats "low-energy day"; a "companion" persona that is saccharine or condescending; adaptivity that becomes unpredictable or untrustworthy; false intimacy.

## 10. Studio F — Category Breaker

> **Mandate (verbatim, `prd.md` §8):** Challenge every convention of habit apps.

- **Framing question:** If we refused to assume checklists, streaks, reminders, progress dashboards and daily opens were necessary, what would a behavior-change product for midlife women even be?
- **Lens / worldview:** **First-principles contrarian.** Interrogate and discard category conventions (the checkbox, the streak, the daily-open loop, the stat dashboard) and invent alternatives. This studio is expected to lean hardest on **invention** — which makes **B5 (label invention, not evidence)** and **B7 (no imagined preferences as validated)** bind hardest here.
- **Atlas emphasis:** read the *whole* Atlas as a set of problems to solve unconventionally; no single territory is "home." Explicitly licensed to attack conventions other studios take for granted.
- **What a strong concept looks like here:** breaks at least one deep category assumption with a *defensible* rationale tied to a user problem and a mechanism (not novelty for its own sake); still clears every mandatory gate (B6); is different in *kind*, not just in skin, from the other five studios' likely directions.
- **Self-critique agenda:** Is the break grounded in a real user problem and mechanism, or is it novelty theatre? Does breaking the convention also break the *behavior-change value* (throwing out the mechanism with the UI)? Is it still usable, accessible and trustworthy (B6)? Can its appeal be *tested* (`→ TASK-048`), or is it only clever?
- **Studio-specific traps to avoid:** novelty for its own sake; discarding a convention that was actually carrying the mechanism; "different" that is merely confusing or inaccessible; invention presented as if it were evidenced; cleverness that cannot be validated.

## 12. Forbidden values & actions

These make a commission or a brief **invalid**, not merely weak. They are the structural isolation- and anti-fabrication guards, mapping to `prd.md` §3/§4/§8/§11/§13.

### 12.1 Gate & package integrity
1. **Commissioning before the gate** (violates B1): issuing a brief or starting a studio before the Program Director's §7 Atlas-release **pass** and a logged `PKG` version. → reject; no studio begins.
2. **Per-studio package curation** (violates B2): giving one studio more, less, or differently-framed evidence than its siblings. → reject; re-issue the canonical `PKG`.
3. **Unsynchronized package** (violates B2/§2.2): a studio running on a different `PKG` version than the others. → reject; re-sync all six.

### 12.2 Isolation (the core of this task)
4. **Cross-studio concept sharing before the first review** (violates B3/§3): any studio viewing/receiving another's ideation, concepts, storyboards or lead pick before Gate 3. → independence breach; quarantine affected concepts from the comparison (§3.3).
5. **Sequestering the *evidence*** (inverse error): withholding shared `PKG`/repository evidence from a studio in the name of "isolation." → reject; evidence is *always* shared (§3.1). Isolation sequesters concepts, never evidence.
6. **Missing independence attestation** (violates S-6): a submission with no signed attestation of package version + non-viewing. → incomplete; cannot enter the comparative review.

### 12.3 Fabrication & invention laundering
7. **Fabricated research in a brief** (violates B7, `prd.md` §4/§11): inventing a user finding, quote, metric, effect size or clinical outcome in the briefing material. → reject; gravest violation.
8. **Invention presented as evidence** (violates B5, `prd.md` §11): a brief (or later a concept) labelling an invented mechanism as a finding rather than an invention. → reject; re-label.
9. **Imagined preference asserted as validated** (violates B7, Prompt 09): stating or implying that a direction is desirable/effective without a test. → reject; convert to a test hypothesis (`→ TASK-048`).

### 12.4 Scope & mandate
10. **Concepts inside the brief** (violates BC-9, scope): the briefing document itself proposing ideas, concepts, wireframes or storyboards. → reject; the brief sets the mandate, the studio creates the concepts.
11. **Competitor feature-copying licensed** (violates B4, `prd.md` executive mandate/§13): a brief instructing a studio to replicate a competitor feature list rather than reason from mechanism + evidence. → reject.
12. **Collapsed divergence** (violates B1/§8): six briefs that are not meaningfully distinct (same framing/emphasis), guaranteeing six variations of one vision. → reject; restore distinct lenses.
13. **Mandatory gate made compensable** (violates B6, `prd.md` §9/§11): a brief that frames clinical/privacy/accessibility/autonomy as a trade-off against delight/novelty. → reject; gates are non-compensable.

## 13. Governance, dependencies, and change control

- **Custodian:** the **WS07 Concept Program Lead** owns the briefs and the `PKG` assembly under the **Program Director** as independence custodian (the role that enforces §3 and cuts package versions). The six studios are *run by*, not *owned by*, this role; each studio has its own internal lead. Roles are accountable **role types**, not named individuals; staffing overlap is allowed but bound by S-2/S-6 (`↔ TASK-002/003`).
- **Where these briefs sit in the pipeline:** downstream of the approved, prioritized Atlas (`↔ TASK-041/042`; the §7 hard stop) and the capability decisions (`↔ TASK-009`); upstream of the concept submissions (`→ TASK-044`), the wireframe spec (`→ TASK-045`), and comparative validation + final selection (`→ TASK-048`). They realize **WS07 / Gate 3** (`prd.md` §11: "independent studio outputs, complete journeys, invention clearly distinguished from evidence").
- **Dependencies:**
  - `↔ TASK-041 / TASK-042` Opportunity Atlas schema & prioritization rubric — supply P1, the approved territory-mapped problem space that gates into these briefs; both name `→ TASK-043` as their downstream consumer.
  - `↔ TASK-009` Decision & experiment registers — supply P2 capability `DEC` verdicts and receive each studio's **test hypotheses** as `EXP` entries.
  - `→ TASK-029 / TASK-027 / TASK-028` User-needs synthesis, interview guide, diary kit — supply P3 real user findings (labelled executed/unexecuted).
  - `→ TASK-024 / TASK-025` Behavioral literature protocol & evidence-extraction table — supply P4 BCT/mechanism evidence and ethical anti-patterns.
  - `→ TASK-006 / TASK-011 / TASK-012 / TASK-016` Benchmark registry, listings, comparison matrix, test journeys — supply P5 reference patterns (reference, **not** a feature menu, B4).
  - `↔ TASK-001` Success-metrics spec — supplies P8 and the zero-guilt North Star the concepts design toward.
  - `→ TASK-033 / TASK-040 / TASK-022` Safety gate, privacy/clinical boundary, iOS/accessibility audit — supply P7, the non-compensable constraints (B6); R14/R15/R13 bind hardest on Studios D, C/E.
